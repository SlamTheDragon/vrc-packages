### 1.1 Preview Channel Readiness: 94% (Near Ready)

The subsystem on branch `preview/crawler-network` shows strong preview capabilities. The code enforces bounded claim scans (`MAX_CLAIM_SCAN_PAGES = 3`). The crawler node uses fixed lease deadlines and durable SQLite WAL outbox buffering. The repository uses Docker volume isolation and structured `latest.log` broadcasts.

Only two operational items block preview deployment:
1. Pushing 15 verified local commits from `preview/crawler-network` to `origin/preview/crawler-network`.
2. Resolving the frozen Linux crawler preview tag deadlock (`R50-C31-RECOVERY`).

### 1.2 Production Release Readiness: 51% (Strictly Blocked)

Production release readiness remains low. Five systemic blockers prevent release to production:
1. **SDK Release Hold (Gate G15)**: The owner hold in `AGENTS.md` blocks publication of SDK `v0.1.0`. The hold requires a complete review of all API routes, permissions, and SDK methods.
2. **Edge Isolate Rate Limiting**: The coordinator uses process-local memory for rate limiting. Cloudflare Workers do not share memory across global edge locations.
3. **Worker Robots Egress Gap (`R24-C21`)**: Cloudflare Workers runtime lacks `node:dns` lookup and `node:https` servername APIs. The coordinator cannot perform safe direct robots fetching without DNS rebinding risks.
4. **Unindexed Database Scans**: The D1 database lacks indexes on 10 high-frequency query paths. Growing tables will cause full scans and exhaust Worker CPU budgets.
5. **Contract Cracks and Audit Blind Spots**: Administrative endpoints discard audit parameters. The coordinator maps database exceptions to HTTP 409 Conflict. The crawler node lacks transport-level binary download rejection.

## 2. Subsystem Architecture and Contract Health Audit

This section evaluates the code, schemas, and API contracts across the repository.

### 2.1 Coordinator Subsystem (`src-worker`)

The coordinator runs as a Cloudflare Worker using D1 storage. It manages leases, stores observations, and serves downstream consumer APIs.

#### 2.1.1 D1 Schema Architecture and Documentation Drift

The coordinator does not use Wrangler migration files. The authoritative DDL exists as an inline string (`D1_SCHEMA_SQL`) in `src-worker/src/storage/d1/utils.ts:34-108`. Schema initialization occurs via `POST /v1/operator/init`.

Critical differences exist between `docs/source/DATABASE_SCHEMAS.md` and `D1_SCHEMA_SQL`:

1. **User Identity Table**:
   - `DATABASE_SCHEMAS.md:63-75` defines `registered_registrants` with primary key `registrant_id`.
   - `utils.ts:91` implements `registered_users` with primary key `user_id`, `age_verified`, and `is_moderator`.
   - Documentation line 62 contains an unresolved `FIXME` comment.
2. **User Token Prefix**:
   - `DATABASE_SCHEMAS.md:69` specifies token prefix `vrcp_reg_`.
   - `coordinator.ts:2479` enforces regex `/^vrcp_usr_[a-f0-9]{64}$/`. Any `vrcp_reg_` token fails validation.
3. **Audit Log Architecture**:
   - `DATABASE_SCHEMAS.md:108, 275` documents separate tables for actions.
   - `utils.ts:36-65` implements a unified `operator_audit_log` table with 5 SQL views. Direct inserts to view names fail.
4. **Catalog Tombstones**:
   - `DATABASE_SCHEMAS.md:390-397` documents column `tombstoned_at` and primary key `cursor_seq`.
   - `utils.ts:72` implements column `recorded_at` and composite primary key `(canonical_id, recorded_at)`.
5. **Origin Robots Refreshes**:
   - `DATABASE_SCHEMAS.md:145-161` defines two distinct tables.
   - `utils.ts:45-47` folds refresh lease columns into `origin_robots` and provides a compatibility view.
6. **Creator Claims View**:
   - `DATABASE_SCHEMAS.md:527` names the view `creator_claims`.
   - `utils.ts:106` names the view `delegated_creator_claims` and adds a synthetic `action` column.

#### 2.1.2 TypeScript Model Drift in `definitions.ts`

TypeScript models in `src-worker/src/storage/d1/definitions.ts` diverge from the database schema:
- `JobRow` (`definitions.ts:29-34`) omits `created_at` and `robots_deferred_until`. Both columns exist in DDL (`utils.ts:41`).
- `CanonicalPackage` (`definitions.ts:52-61`) omits `publishedAt`, `timestampConfidence`, and `contentRating`. The coordinator must construct ad-hoc intersection types in `coordinator.ts:1881` and `1916`.
- `IdentityLink` (`definitions.ts:63-72`) defines camelCase fields. Raw D1 queries return snake_case database columns.

#### 2.1.3 Unindexed Database Query Paths

Ten high-frequency query paths lack indexes in `src-worker/src/storage/d1/coordinator.ts`. These queries trigger full table scans:

1. `source_items(source_url)` (`coordinator.ts:726, 740, 899`): Queries match on `si.source_url`. The table only indexes `source_key`.
2. `source_leads(target_url)` (`coordinator.ts:751, 781`): Queries match on `sl.target_url`. No index covers this column.
3. `source_leads` GitHub Repo Normalization (`coordinator.ts:680-692`): Scans table and evaluates string expressions on every check.
4. `crawl_jobs(lease_profile_id)` (`coordinator.ts:1385`): Scans table when disabling source profiles.
5. `crawl_jobs(source_rule_id)` (`coordinator.ts:1307`): Scans table when disabling auto-queue rules.
6. `package_fronts(storefront_url)` (`coordinator.ts:2565, 2569`): Scans table twice on every delisting report.
7. `registered_apps(created_at, app_id)` (`coordinator.ts:2985`): Requires an in-memory filesort on operator app listing.
8. `canonical_packages(content_rating)` (`coordinator.ts:3146, 3161`): Scans table and sorts rows on moderator queries.
9. `canonical_packages(COALESCE(published_at, created_at))` (`coordinator.ts:2422`): Scans entire table on general search.
10. `catalog_tickets(ticket_type, recorded_at, ticket_id)` (`coordinator.ts:2613`): Index omits sort alignment for `listTakedownsPage`.

#### 2.1.4 Missing Constraints and Foreign Key Enforcement

- **Foreign Key Enforcement**: The coordinator never executes `PRAGMA foreign_keys = ON;`. Tests run this pragma, but production D1 does not. Cascading deletes on `package_fronts` and `desktop_tool_evidence` fail to execute.
- **Orphaned Deletions**: In `coordinator.ts:2073-2088`, `deleteCanonicalPackage` deletes from `identity_links` and `canonical_packages`. It does not delete from `package_fronts` or `desktop_tool_evidence`.
- **Missing CHECK Constraint**: Column `canonical_packages.content_rating` lacks a `CHECK` constraint.

#### 2.1.5 D1 Query Budgets and Batch Limits

1. **Claim Job N+1 Query Loop**: In `Coordinator.claim()` (`coordinator.ts:358-429`), the coordinator fetches up to 100 candidate jobs. For each candidate, it executes profile selects, lease checks, and write batches. A claim request can execute over 300 D1 operations, risking worker timeouts.
2. **Offset Reset Anomaly**: In `coordinator.ts:427`, deferred jobs reset `offset = 0`. The coordinator re-scans the initial page, causing repeated scans.
3. **Unbounded Batch Statements**: Cloudflare D1 limits batches to 128 statements. In `Coordinator.submit()` (`coordinator.ts:997`), `disableAutoQueueRule()` (`line 1325`), and `disableSourceAccessProfile()` (`line 1408`), code pushes statements into `batchStmts` without chunking. Batches with over 128 statements fail with runtime exceptions.
4. **Unpaged Origin Delay Loop**: In `coordinator.ts:246-259`, `approvedDueProfileDelayForOrigin` selects all due jobs for an origin without a `LIMIT` clause. It executes individual profile queries in a loop, exhausting subrequest limits.
5. **Sequential Result Submissions**: In `Coordinator.submitBatch()` (`coordinator.ts:1023-1055`), the coordinator sequentially awaits `this.submit()` for each result. A batch of 10 results executes 50 to 300 queries sequentially.
6. **Isolate Rate Limiter Volatility**: `InMemoryRateLimiter` (`rate_limiter.ts:39-92`) stores counters in local isolate memory. Edge requests across different Cloudflare data centers bypass limits.

#### 2.1.6 Security and Capability Token Authorization

- **Token Format**: The system uses `vrcp_<entropy_64hex><capability_4hex>`. Token hashing via SHA-256 protects stored credentials.
- **Capability Bypass Defect**: In `Coordinator.authenticate()` (`coordinator.ts:279`), the check `if (isCapabilityToken(bearer))` is optional. If a token matches `token_hash` but does not match the capability format, the code skips capability verification. The coordinator must reject non-conforming tokens.
- **Permission Matrix**: All endpoints enforce authentication. Missing tokens fail closed with HTTP 401 or 403.

#### 2.1.7 Error Handling and Audit Loss

- **Incorrect 409 Conflict Mapping**: In `operator_handler.ts:394-401`, unhandled database exceptions map to HTTP 409 Conflict. Database errors must return HTTP 500 Internal Server Error.
- **Discarded Audit Parameters**:
  - `adjustPackageRating` (`coordinator.ts:3193`) validates `reason`, but never inserts it into the database.
  - `setAppDelegation` (`coordinator.ts:3090`) accepts `actor` and `reason`, but writes neither to logs.
  - `reviewAppCandidate` (`coordinator.ts:3032`) accepts `actor` and `notes`, but discards both.
- **Schema CHECK Constraint Gap**: Table `operator_audit_log` restricts `entity_type` to `('node','lead','job','rule','profile')`. The constraint blocks auditing for `'app'`, `'rating'`, and `'user'`.
- **Content-Type Error Code**: `readJson` (`handler.ts:41-44`) throws status 403 for invalid media types instead of standard 415.

### 2.2 Crawler Node Subsystem (`src-crawler`)

The crawler node fetches metadata under leases granted by the coordinator.

#### 2.2.1 Lease Timing and Lifecycle Bounds

- **Batch Claim Array Dropped**: In `src-crawler/src/runner/daemon.ts:248, 262`, the daemon calls `client.claim()` without arguments and destructures `{ job } = claim;`. It discards `claim.jobs`. If the coordinator returns a batch, extra jobs remain locked in D1 until their 5-minute leases expire.
- **Fixed Leases**: Coordinator leases expire after 300 seconds (`coordinator.ts:389`). Heartbeat calls verify lease validity, but do not extend expiration (`coordinator.ts:289-312`).

#### 2.2.2 Monotonic Deadlines and Clock Skew Vulnerability

- **Wall-Clock Reliance**: The crawler measures lease expiration using `remainingMs = expiresAtMs - Date.now()` (`lease_runner.ts:58`).
- **Clock Skew Risks**:
  - If the crawler clock is slow, `remainingMs` increases. The crawler continues fetching after the coordinator expires the lease.
  - If the crawler clock is fast, `daemon.ts:266` rejects claimed jobs as expired before execution.
  - If the clock jumps backward during sleep, the node freezes in an idle loop (`daemon.ts:430`).
- **Discarded Server Time**: `HeartbeatResponse` returns `serverTime` (`node_protocol.ts:76`). The crawler client discards this value (`node_client.ts:175-180`). The crawler maintains no clock offset adjustment.

#### 2.2.3 Fail-Closed Coordinator Loss vs Outbox Expiration

- **In-Flight Cancellation (Verified Pass)**: Heartbeat pulses run every 5,000 ms. If the coordinator becomes unreachable, `pulse` catches the error and calls `authority.abort()` (`lease_runner.ts:45-51`). The abort signal destroys the HTTPS socket in `public_metadata_fetch.ts`. Active fetching terminates immediately.
- **Outbox Buffer Expiration Gap**: The crawler buffers completed outcomes in SQLite `node_outbox`. If a coordinator outage lasts longer than 5 minutes, buffered leases expire. Upon recovery, the coordinator rejects submissions with terminal code `lease_expired` (`coordinator.ts:1045`). The crawler marks entries terminal and deletes them (`daemon.ts:180-182`). All buffered data is lost.

#### 2.2.4 Source Access Profiles and Orphaned Robots Enforcer

- **Orphaned RobotsEnforcer (Critical Defect)**: `src-crawler/src/utils/robots/robots.ts` implements a full RFC 9309 `RobotsEnforcer`. Grep searches show that runtime files (`daemon.ts`, `lease_runner.ts`, `observation_adapter.ts`) never import or call this class. The crawler node performs zero local robots checks during crawling.
- **Zero Binary Download Gap (Critical Policy Defect)**: Project rules in `LEGAL.md:80` and `AGENTS.md:19` prohibit binary asset downloads. In `src-crawler/src/client/public_metadata_fetch.ts:15-83`:
  - The fetcher caps response sizes at 2 MB.
  - The fetcher does not inspect URL paths for `.zip`, `.unitypackage`, or `.exe`.
  - The fetcher does not validate `Content-Type` headers (`application/zip`, `application/octet-stream`).
  - Binary files smaller than 2 MB are downloaded into memory over TLS before parsing fails in `observation_adapter.ts`. This violates zero-binary covenants.

#### 2.2.5 Orphaned Resilience Modules

- `AdaptiveRateLimiter` (`src/utils/resilience/adaptive_limiter.ts`) and `DomainCircuitBreaker` (`src/utils/resilience/circuit_breaker.ts`) exist in the codebase.
- Neither class is wired into production runners. Only unit tests reference them. The coordinator handles origin pacing in D1.

#### 2.2.6 Ingestion Error Handling Edge Cases

- **Rate Limit Calculations**: `access_outcome.ts:29` calculates `retryAfterSeconds` using local `Date.now() / 1000`. Clock skew distorts upstream rate limit delays.
- **Challenge Detection**: The adapter detects Cloudflare Turnstile headers and HTML challenges, applying 3-day backoff blocks.
- **XXE Injection Protection**: The adapter rejects XML sitemaps containing `<!DOCTYPE` or `<!ENTITY`.
- **Outbox Backpressure**: When pending outbox entries exceed 1,000, the daemon pauses claims (`daemon.ts:240-246`).
