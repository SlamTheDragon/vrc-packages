This matrix records primary terms, robots, and interface evidence across target platforms. Fixed historical pacing delays and old bootstrap expiry dates do **not** establish source clearance. Every origin requires separate **Fetch**, **Retain**, **Publish**, and **Remove** decisions, an active loose steering profile (`steering_profiles` per Version 0 blueprint, migrating from `source_access_profiles`), and delegated RFC 9309 `robots.txt` preflight before live crawling.

## 2. Per-Origin Clearance Record Requirements

Every approved steering profile (`steering_profiles`) provisioned in D1 must trace to a documented review recording:
1. Domain-pool host match (`exact`, `wildcard_subdomain`, or `any_vpm_https`), path scope, pagination query mode, and `GET`-only method constraint.
2. Primary terms URL, effective date, retrieval date, and applicable clause summary.
3. Live delegated RFC 9309 `robots.txt` verification result (never a fabricated allow body).
4. Configured `min_delay_ms`, `recrawl_interval_ms`, `expires_at`, bot identity (`VRCPDiscoveryBot/{version}`), `retain_classes`, and `publish_classes`.
5. Instant disable kill-switch and objection revocation contact path (see [`expansion_action_matrix.md`](../legal/expansion_action_matrix.md#2-five-step-source-objection-and-takedown-workflow)).
